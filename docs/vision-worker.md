# Vision risk worker

The optional worker fits two pixel-risk models against independent Blender RGB-error labels. Both read the current condition’s predicted target RGB and 26 registered deployable features. L2-frozen trains the projection and risk head. L2-vision-ft also updates pretrained blocks 10 and 11 and the terminal LayerNorm of the plain DINOv2 ViT-S/14. The original NumPy L1 scorer remains available. [Official backbone implementation at the registered revision](https://github.com/facebookresearch/dinov2/tree/7764ea0f912e53c92e82eb78a2a1631e92725fc8) · [Registered base identity](../configs/vision-base-v1.json)

## CPU installation

For the existing L1 scorer, install `evidence-lens` from the release wheel or a source checkout. For the vision modes on macOS with Apple Silicon, run `python -m pip install '.[vision]'` in a project checkout and a fresh Python 3.11 or 3.12 environment. On Linux or Windows CPU, install PyTorch's CPU wheel first and then install the same project extra.

```sh
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install ".[vision]"
```

Use the platform's Python environment for either command. The research GPU worker has a separate CUDA-enabled PyTorch installation. [PyTorch 2.8.0 platform instructions](https://pytorch.org/get-started/previous-versions/#v280)

## Inputs and official base

Use Python 3.11+, PyTorch 2.8, NumPy, Pillow, safetensors and psutil. Windows uses the CUDA-enabled PyTorch environment. The training handoff includes the necessary original Evidence Lens CPU source. The model’s independent CPU package can run with those dependencies and local files. The Windows scientific call runs inside the recorder and inherits its new `EL_RUN_ID`.

Set `SOURCE` to the unmodified official source tree, `PTH` to the original pretrained checkpoint. Commands below use POSIX environment variables. In PowerShell use `python`, `$env:NAME` for environment variables, and complete each command on one line. Pass an unused or empty output directory.

```sh
python scripts/vision_worker.py pin-base --official-source "$SOURCE" --revision 7764ea0f912e53c92e82eb78a2a1631e92725fc8 --expected-checkpoint-sha256 b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9 --output base-pin
python scripts/vision_worker.py verify-base --official-source "$SOURCE" --base "$PTH" --base-pin base-pin/base.json --output base-check
```

The checkpoint is 88,283,115 bytes. The original project-specific Windows source TAR is 4,157,440 bytes with SHA-256 `e36bd6bfa8d2dd773824c6968a74a194587a299ed6039984b5214396ed2768ac`. The source LICENSE digest is `600cc67cc4cb2f5ea317dcfc687ad1c74dc4bec8782bbe9db0afd83513b935b7`. A clean Git checkout can generate the per-file source pin independently. Supply `--source-archive EXACT_TAR` in place of `--official-source` to register the original TAR. For forward verification the source must be an extracted tree with exact original Git blob bytes. The worker disables xFormers and uses the official constructor with `pretrained=False`, then loads the supplied hash-checked raw tensor dictionary into both implementations with strict keys and verifies the 324 × 384 FP32 patch tokens on a fixed numerical input.

The image path uses the complete native display-sRGB grid. Nonfinite source pixels are replaced with black for encoding and remain ineligible at their native coordinates. The longer side scales to 252, the other side rounds half up and the frame is centred with mean-colour padding. The 18 × 18 descriptor grid is projected from 384 to 32 channels before native sampling. Bilinear interpolation uses original pixel centres and each patch’s observed-area fraction. Coordinates outside the image contribute no observations. Each mapped descriptor joins its 26 train-normalized numerical features in a 58 → 32 → 1 GELU head. Sigmoid outputs are risk scores. The frozen operating point uses strict low risk `score < tau`.

## Recorded engineering pilot

The train transport contains precisely the four registered pilot families, with six original target predictions per family. `TRAIN` is its signed `dataset.json`. `PRE` points to the separately recorded pilot-only `preprocessing.json`. Select their externally recorded SHA-256 values. The original base pin generated by the registered Git commit has SHA-256 `7c136f77370a1bb00a00ff94f946dc88f00c0aeefd11194071d4f3f9e7a45f85`. `CAT` is the registered stage-two families catalog and `CAT_SHA` its independently verified digest.

```sh
python scripts/vision_worker.py configure --phase pilot --branch L2-vision-ft --seed 1729 --head-lr 0.0003 --backbone-lr 0.00001 --epochs 20 --max-updates 32 --train "$TRAIN" --train-sha256 "$TRAIN_SHA" --preprocessing "$PRE" --preprocessing-sha256 "$PRE_SHA" --base-pin base-pin/base.json --base-pin-sha256 "$PIN_SHA" --catalog "$CAT" --catalog-sha256 "$CAT_SHA" --output pilot-config
python scripts/vision_worker.py pilot --train "$TRAIN" --preprocessing "$PRE" --official-source "$SOURCE" --base "$PTH" --base-pin base-pin/base.json --config pilot-config/config.json --device cuda --output "$OUT"
```

Run the second command as a recorded model-fit operation, with the exact config, data parents, official source/checkpoint and source handoff bound by their original manifests. The model performs at most 32 AdamW updates. It uses microbatch one, accumulation four, FP32 arithmetic, constant rates and weight decay 0.01. The target loss is mean binary cross-entropy over each view’s fixed eligible sample, weighted equally by supervised family and then by its supervised views. The last partial group uses its actual number of views. Registered trials use the same seed, sample IDs, head initialization and order under both branch settings. All 12 transformer blocks run every forward.

## Formal fit, selection and resume

Use the 28-family train manifest, train-only preprocessing and eight-family development manifest. Configure with `--phase train` and add `--development "$DEV" --development-sha256 "$DEV_SHA"`. Omit `--max-updates`. Run the `train` command with the same inputs as the pilot and add `--development "$DEV"`.

| Branch | Seed A configurations |
| --- | --- |
| L2-frozen | Backbone rate 0. Head rate 0.0001 or 0.0003. |
| L2-vision-ft | Backbone rate 0.00001 or 0.00003. Head rate 0.0003. |

Supply seed 1729 for A. Stop after at most 20 epochs or three consecutive epochs without improvement. Each epoch uses the registered development common domain, whole FP32 ties, and AP for views containing both classes. Defined views are averaged within family, then families receive equal weight. The earliest highest AP identifies the run’s checkpoint. After the selected tensors are restored, all development B0 targets are rescored to freeze the closest attainable family-mean 80% low-risk coverage over reference-valid pixels, with full tie groups and lower coverage winning an exact tie.

Register `roster.json` as `{"schema":"el-vision-candidate-roster-1","stage":"learning-rate","runs":[{"run_id":"...","manifest_sha256":"..."}]}` with four authentic model-fit runs. Each training result is at `payload/training.json`. The Mac selector reads the original recorder seals, training receipts and model indices.

```sh
python scripts/vision_worker.py select --stage learning-rate --store "$STORE" --roster roster.json --output lr
```

For a recorded selection, keep the returned fits in the active store and run `scripts/stage2_candidate_selection.py --stage learning-rate --store "$STORE" --shelf "$SHELF"` with one `--fit RUN_ID=MANIFEST_SHA256` argument for each of the four candidates. Use `--stage primary` with all eight runs after the paired repeats finish. The recorder links every training receipt and model index and writes the selected identities to `payload/selection.json`.

Repeat the chosen rate for **both** branches at 2718 and 3141. Include `--lr-selection lr/selection.json --lr-selection-sha256 "$LR_SHA"` with `configure` and `--lr-selection lr/selection.json` with `train`. Use a final roster with stage `primary` and all eight runs. The selector returns seed A for each model and records all candidates and repeat results. The separate independent evaluation freezes both models with the original five before the new test cohort opens.

Each scientific run writes `setup.json`, trainable optimizer names and counts, per-epoch curves, `gradient-witnesses.json` with individual minibatch data-only gradients measured before optimizer decay, and `parameter-changes.json` with final numerical changes and byte-identical frozen tensors. The self-contained model contains all FP32 weights in safetensors. A private `training-state.pt` holds only keyed state with validated tensors and optimizer state. An explicit recorder retry may use `--resume FILE --resume-sha256 DIGEST` with the same config, source and data pins and a new destination. Mid-epoch snapshots save the next view cursor at update boundaries. The selected model is checked against a fresh CPU load on actual authorized training inputs.

## CPU deployment and independent evaluation

From the exported `package/` directory use its hash-checked numerical model, `requirements.txt` and CPU runtime. `MODEL_SHA` identifies `model.json`. The first interface accepts only the supplied prediction RGB and deployment arrays. The native interface computes camera projection and all features directly from the calibrated original source and prediction files.

```sh
python -I infer.py --model-sha256 "$MODEL_SHA" --rgb target-rgb.npy --deploy target-deploy.npz --output raw-score
python -I score-native.py --model-sha256 "$MODEL_SHA" --input input.png --cameras cameras.json --predictions predictions --view all --warm-repeats 3 --output native-cost
```

On native 512 × 512 formal views the second command records process-to-first-output time, warm p50 and p95, process-tree sampled peak RSS, per-case support and the bytes consumed. It includes file reads, target/source camera projection, feature construction, the complete backbone, head and output serialization. The precomputed-array interface measures a different workload. A missing render or unsupported depth encoding retains its explicit status and unknown values. The independent deployment decision uses the preregistered Mac p95 ≤5 s per view and peak ≤2 GiB criteria alongside paired development performance. Preserve both neural checkpoints even if L1 stays the default.

For a full development score transport use `vision_worker.py infer-dataset --split development --package PACKAGE --model-sha256 SHA --dataset DEV/dataset.json --dataset-sha256 DEV_SHA --device cpu --output NEW`. The per-view output uses `risk`, `valid` and `state`, with 255 for unknown. The Mac test entry additionally requires `--split test --store STORE --shelf SHELF --catalog CATALOG --catalog-sha256 CAT_SHA --method-freeze METHOD --method-sha256 METHOD_SHA` and the independent evaluator's frozen source. It authenticates the eight-family opening and selected model before opening the test manifest.

## Recorded Windows dispatch and Mac intake

Each parent argument uses the original `RUN_ID=MANIFEST_SHA256`. Prepare one directory per registered configuration on the Mac. The train/development roots on Windows contain `dataset.json` and the exact files listed beneath it. The directory survives job retries and is independently checked against the intake manifest on each execution. The external GPU lock covers the entire Windows command.

```sh
python3 scripts/vision_gpu_job.py prepare --store "$STORE" --shelf "$SHELF" --core-repo . --worker "$WORKER" --worker-sha256 "$WORKER_SHA" --config "$CONFIG" --config-sha256 "$CONFIG_SHA" --train "$TRAIN_PARENT" --development "$DEV_PARENT" --preprocessing "$PRE_PARENT" --base-pin "$BASE_PARENT" --base-check "$CHECK_PARENT" --output "$JOB"
```

Omit `--development` for a train-only pilot. For the repeat seeds, add `--lr-selection RUN_ID=MANIFEST_SHA256`. Transfer the complete prepared job and the signed split directories. Supply the SHA of `job.json` from the printed dispatch receipt. From PowerShell on the GPU worker run the local job script with its calibrated Python environment.

```powershell
python "$Job/code/scripts/vision_gpu_job.py" run --job "$Job" --job-sha256 "$JobSHA" --store "$Store" --return-dir "$Returns" --train-root "$Train" --development-root "$Dev" --official-source "$DinoCheckout" --base "$DinoPth"
```

Successful duplicate dispatches reuse the existing run and return receipt. If the original run failed, an explicit `--retry-of RUN_ID` retains the failure; to resume, add `--resume-sha256 SHA` for its sealed checkpoint. The returned `transport-audit.json` identifies the exact data/worker receipts. The selected formal checkpoint's native development arrays and strict states are listed in `payload/development-scores/scores.json`. A completed training receipt includes the CPU-reloaded digest table of all 181 tensors. The setup receipt records the actual PyTorch precision/determinism flags and the cuBLAS workspace setting. Eight data-only BCE minibatches record all required gradient groups.

```sh
python3 scripts/vision_gpu_job.py receive --job "$JOB" --job-sha256 "$JOB_SHA" --store "$STORE" --archive "$RETURN_ZIP" --receipt "$RETURN_RECEIPT"
```

The Mac independently checks the job, run seal, stage inputs and archive member hashes. Keep the original Windows archive and return receipt for provenance. The train-only pilot and formal worker have separate scientific identities.
