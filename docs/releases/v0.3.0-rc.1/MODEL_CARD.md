# Multi-source prediction risk

The training unit is a registered camera view of one authored static world under one fixed Gaussian reconstruction. A target-pixel label is positive when its display-RGB mean absolute error exceeds float32 0.05 against the original independent Blender reference. State 255 retains unsupported pixels. All comparison grids preserve the original 256×256 resolution and their own denominators.

Eight families supply training, four supply model selection and four supply the single held-out confirmation. Two- and four-image reconstruction change the representation itself. Score-one, score-two and score-all hold a reconstruction fixed while changing the evidence available to the scorer. The Stage B logistic transfer always consumes s00 with its original threshold. The three multi-source methods reuse their single score-all development threshold across source ablations.

Both neural branches start from the same publicly released Stage B DINOv2 ViT-S/14 fine-tuned backbone. Each seed gets a fresh shared head and projection. MS-frozen updates these six tensors. MS-ft also updates the last transformer block and final layer normalization. The Gaussian scene fit and the error-risk fit have separate parameters, objectives and recorded optimizer histories. The released primary models use seed 1729. Seed 2718 measures sensitivity. The pre-test decision, all four independent tensor proofs, actual CPU costs, numerical comparisons and resource failures are linked from release.json and the numerical archive.

The trained heads consume the predicted target image plus 39 projected numeric and categorical features. They never require an independent target reference at deployment. The study covers authored opaque worlds, a prescribed calibrated camera rig and a fixed Gaussian optimization budget. These data do not establish performance on uncalibrated photographs, moving objects or other reconstruction budgets.

All four registered fits reached 288 optimizer updates. The earliest maximum development AP in each fit was epoch 12. Independent checks matched the four first-update BCE gradients against the original supervision and verified eight recorded pre-weight-decay gradient witnesses per fit. Across seeds 1729 and 2718, respectively, the frozen backbone changed zero scalars and the fine-tuned backbone changed 1,775,998 and 1,775,995 of 1,776,000 eligible scalars. Both branches changed all 14,657 newly initialized projection and head scalars at both seeds. Each trained package contains all 181 FP32 tensors.

The original seed-1729 frozen Windows job stopped after it wrote the learned weights and development maps. A model-index schema error prevented the package from loading. A separate Mac export retained the weight file and all 48 selected all-source maps byte-for-byte. It performed zero further optimizer steps. On the 3,101,930 supported development pixels, Mac CPU and Windows all-source scores agreed within 0.00002572, with three changes of side at the strict threshold. Windows scores remain the recorded basis for model selection. The archive includes the two executable source versions and the individual tensor and development-map checks.

On the registered offset-bell-cage development case, the four-thread Mac warm score-all p95 is the **single-target latency measured across six views**, one observation per target. It was 0.076 s for MS-frozen M2, 0.154 s for MS-frozen M4, 0.079 s for MS-ft M2 and 0.106 s for MS-ft M4. The model was loaded once before the warm loop. Each timed call verified and read the pre-rendered inputs, projected allowed sources, preprocessed the image, ran the network and wrote the compressed score arrays. A cold score-all v01 process took 0.576–0.644 s from before Python startup through exit. The sampled peak of each warm process tree ranged from 403.7 to 426.6 MB. An isolated six-view score-all batch wall time was not recorded. Reconstruction, GPU rendering and reference evaluation have separate timing records. ## Held-out confirmation

The four held-out families contributed 48 native target renders. Under two-source reconstruction, common-domain AP for MS-L1, MS-frozen and MS-ft was 0.747, 0.727 and 0.734. Under four-source reconstruction these values were 0.704, 0.651 and 0.665. MS-L1 remained the development-selected default. Every reported target used its own prediction and reference masks. [Full counts and operating points](https://github.com/wany614/evidence-lens/blob/v0.3.0-rc.1/docs/results/multisource-confirmation.md)

## Installations verified after publication

The public archives were downloaded anonymously and run on macOS arm64, Windows AMD64 and Debian 13 Linux arm64 under OrbStack. The two arm64 checks used Python 3.12.16 and the Windows check used Python 3.12.10. Each replay compared all four methods in 120 distinct native outputs and independently checked 12 reference targets. Against the published CPU maps, macOS had zero threshold crossings, Windows had two and Linux had one. [Public verification receipts, numerical differences and exact environments](../../verification/v0.3.0-rc.1/README.md)

## Subsequent frozen photographic evaluation

The published CPU package and all four sets of parameters and thresholds were used unchanged on one external physical object, DTU scan6. With four sources the default MS-L1 common-domain AP was 0.91090 against view-equal prevalence 0.89892, and its frozen low group covered 2,378 of 393,216 pixels. Of those, 1,958 exceeded RGB MAE 0.05. The 256-pixel crop used known calibration, with high target reconstruction error before scoring. The study registered no risk training or recalibration. [Complete measurements and scope](../../results/dtu-external/README.md)

### Subsequent reconstruction study, 23 November 2026

The release was applied again after a new upstream reconstruction was selected using scan1 target quality. Scan6 was now an exposed regression case. On its four-source reconstruction, 174,318 of 393,216 pixels exceeded RGB MAE 0.05. MS-L1 accepted 118,537 pixels as low risk and 32,914 of those were errors. Its common-support AP was 0.5890 at view-equal prevalence 0.4456. At matched 20% coverage on the eight-score intersection, MS-L1 accepted 26,925 errors and MS-ft accepted 28,178, each among 78,642 pixels. MS-ft common AP was 0.5912. MS-L1 remains the released default. The additional evidence covers the registered lighting, centre crop and cameras of this single building regression.
