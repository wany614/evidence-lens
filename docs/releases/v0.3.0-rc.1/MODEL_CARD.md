# Multi-source prediction risk

The training unit is a registered camera view of one authored static world under one fixed Gaussian reconstruction. A target-pixel label is positive when its display-RGB mean absolute error exceeds float32 0.05 against the original independent Blender reference. State 255 retains unsupported pixels. All comparison grids preserve the original 256×256 resolution and their own denominators.

Eight families supply training, four supply model selection and four supply the single held-out confirmation. Two- and four-image reconstruction change the representation itself. Score-one, score-two and score-all hold a reconstruction fixed while changing the evidence available to the scorer. The Stage B logistic transfer always consumes s00 with its original threshold. The three multi-source methods reuse their single score-all development threshold across source ablations.

Both neural branches start from the same publicly released Stage B DINOv2 ViT-S/14 fine-tuned backbone. Each seed gets a fresh shared head and projection. MS-frozen updates these six tensors. MS-ft also updates the last transformer block and final layer normalization. The Gaussian scene fit and the error-risk fit have separate parameters, objectives and recorded optimizer histories. The released primary models use seed 1729. Seed 2718 measures sensitivity. The pre-test decision, all four independent tensor proofs, actual CPU costs, numerical comparisons and resource failures are linked from release.json and the numerical archive.

The trained heads consume the predicted target image plus 39 projected numeric and categorical features. They never require an independent target reference at deployment. The study covers authored opaque worlds, a prescribed calibrated camera rig and a fixed Gaussian optimization budget. These data do not establish performance on uncalibrated photographs, moving objects or other reconstruction budgets.

All four registered fits reached 288 optimizer updates. The earliest maximum development AP in each fit was epoch 12. Independent checks matched the four first-update BCE gradients against the original supervision and verified eight recorded pre-weight-decay gradient witnesses per fit. Across seeds 1729 and 2718, respectively, the frozen backbone changed zero scalars and the fine-tuned backbone changed 1,775,998 and 1,775,995 of 1,776,000 eligible scalars. Both branches changed all 14,657 newly initialized projection and head scalars at both seeds. Each trained package contains all 181 FP32 tensors.

The original seed-1729 frozen Windows job stopped after it wrote the learned weights and development maps. A model-index schema error prevented the package from loading. A separate Mac export retained the weight file and all 48 selected all-source maps byte-for-byte. It performed zero further optimizer steps. On the 3,101,930 supported development pixels, Mac CPU and Windows all-source scores agreed within 0.00002572, with three changes of side at the strict threshold. Windows scores remain the recorded basis for model selection. The archive includes the two executable source versions and the individual tensor and development-map checks.

On the registered offset-bell-cage development case, full score-all CPU inference included loading the inputs, checking their identities, projecting all selected source views and running the model. With four Mac CPU threads, warm six-view p95 was 0.076 s for MS-frozen M2 and 0.154 s for M4. MS-ft took 0.079 s and 0.106 s respectively. Cold score-all wall time across the four cases ranged from 0.576 to 0.644 s, and sampled warm process-tree RSS ranged from 403.7 to 426.6 MB. Exact platform, timing, memory and per-array comparisons are in the CPU evidence.
