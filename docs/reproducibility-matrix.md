## Reconstruction recovery on the same release

| Task | Public inputs and measured outcome |
| --- | --- |
| Rebuild the synthetic starting state | The release example provides all four source images and known cameras. The macOS replay reproduced the 66 initial Gaussians and their complete array SHA-256. For each optimizer recipe the public cell export reproduced the two camera files, all four sources and `init.npz` byte-for-byte. Its metadata names the fresh replay run. [CPU commands and verification digests](recovery-reproduction.md) |
| Run the two reconstruction recipes | The exact native worker can be materialized from the listed Git blobs. The Windows CUDA runs fitted each recipe on the authored control and the photographed set1 development object. A third-party GPU replication needs its own measured software and hardware environment. [Worker and fixtures](../reproduce/recovery-worker-v1/README.md) · [Study results](results/reconstruction-recovery/README.md) |
| Inspect or regenerate the DTU comparison | Source images and calibrated reference crops require access to the official authors’ data. The public records carry the data identities, decision chronology and measurements. Full photo boards and original floating-point renders are held in the private research archive. The control Mac ran macOS 27.2 arm64. Windows supplied the native gsplat execution. Both local Linux container sockets were unavailable for this round. The earlier Debian test above exercised the released CPU scorer. [DTU replay](d1/reproduction.md) · [Recovery replay](recovery-reproduction.md) |
