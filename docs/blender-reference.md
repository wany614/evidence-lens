# 首个 Blender 参考包

`configs/reference.json` 固定了 `scene_001_tabletop/v001` 的尺寸、米制几何、物体编号、材质线性色值、区域光、相机位置、采样设置和验收门槛。两个开发相机是 v01 和 v02，另有四个附近视角。所有资产均由仓库内的几何与材质脚本生成。作品中的真实参考图、遮挡、物体编号和源文件仅供评价端使用。

## 运行与复算

正式生成应由项目记录器启动本地参考环境里的 `produce.py`。记录器先写实际配置并快照源代码，再执行下面的工作命令。花括号由记录器替换。

```sh
/path/to/reference-environment/bin/python \
  '{source}/src/evidence_lens/blender_reference/produce.py' \
  --config '{config}' --out '{out}'
```

工作程序要求独立安装 Blender 4.5.16 的 Python 模块、OpenEXR、Pillow 和 NumPy。采样使用 Cycles CPU。它保存一个包含七台相机的 .blend，正式渲染切换内存场景副本的相机。每个视角的原生线性多通道 EXR 及生成脚本均进入包。参考输出目录必须为空，验收失败也保留全部已完成的证据，并通过非零退出码通知记录器。

`verify_reference.py --payload PATH` 在独立进程打开冻结场景，只读核验七个原生 EXR、PNG、数组和相机，重新计算深度、边缘、开发相机的噪声，并用 Blender 自带的 Scene.ray_cast 对不同可见性区域分层抽样。随机数种子固定，每个区域的边缘和内部各抽取最多 32 个像素。附加 `--out NEW_DIRECTORY` 可在新的记录器运行里保存 `reference_readback.json`。完整运行包文件的 SHA-256、输入谱系、封存和接收仍由记录器核验。

复核 1.1 从打开的 .blend 读取实际焦距、传感器、裁剪面、像素长宽比和渲染尺寸，并从 Blender 原生投影矩阵独立计算 K。原生 EXR 的 Position 使用包内 K 和原生 K 各重投影一次，两次最大误差都必须满足预先记录的像素门槛。复核还解码 Blender 自身输出的源 PNG 和模型实际输入 PNG，逐通道比较 8 位值，并记录两个原始文件的完整哈希。

## 允许传给生成器的数据

`input.png` 是唯一输入视角的实际 8 位无损 PNG。`cameras.json` 给出源和目标相机的内参、外参、尺寸、裁剪范围、传感器和角色。Windows 端可以从这两个文件构建输入。PNG 的焦距由对应相机记录给出。

数组按左上开始的行、列存储。OpenCV 相机的 X 向右、Y 向下、Z 向前；c2w 将相机坐标变换到 Blender 的米制世界。K 以整数像素中心为坐标，画幅的左上边界坐标为 −0.5；K_edge 使用协议的边界原点和半整数中心。两者主点差半个像素。协议所定义的最近邻在前一种约定中读取 floor(q+0.5)。无裁剪地减半时，整数中心坐标满足 q'=(q+0.5)/2−0.5。条件 R1 输入应从正式输入的实际 PNG 数值生成。当前实现按显示 sRGB 数值做 2×2 均值并一次舍入至 8 位，供工程核验的产物保存在 validation/source_256.png。

## 真值与验收

`reference/{view}.npz` 保存显示 sRGB 的 FP32 RGB、世界坐标 Position、从 Position 和 w2c 算出的正向轴深 z、物体 ID、几何有效性、可见性及原因、输入射线首个命中物体、膨胀边缘。`reference.json` 给出数据字典及各文件哈希。物体 ID 0 表示没有表面。无效几何写 NaN，有限 RGB 可独立参与画面评价。每个视角的 PNG 从上述 FP32 显示值量化。运行时记录实际 Standard、无 Look、曝光 0、Gamma 1、sRGB 显示及 OCIO 配置哈希，并与 Blender 自己写出的 PNG 比对。

对于源画幅内的真实点，工作程序对冻结世界的实际三角面做首交测试。匹配容差为 max(0.0001 m, 0.0001×距离)。超出画幅或位于源相机后方、没有命中、首交过远和非有限点各有独立原因码。四邻域中物体 ID、表面有效性或可见性变化时标记两侧，然后做半径二像素的方形膨胀。

每个视角的复核报告分别统计有效 RGB、真实背景、具有网格命中却无法确定可见性的像素。原因码 5–9 逐项记录总数、边缘及内部数量。有些边缘射线可能在两种求交实现之间出现微小差异；对原先标为未解析但独立射线给出明确类别的抽样，报告保留位置、原原因和新观察。

校准场景带有一块轴深 2 米的正对平面及一块轴深 1 米的前景色卡。验证在中心和离轴处同时测量射线长度与轴深，比较已知发光色卡与实际显示数值，并在真实降采样图像上定位前景色卡。当输入相机被红色前景盒遮挡的蓝色后方盒在两个开发相机中重新露出时，程序测量其真实连续水平宽度及扣除边缘后的面积。每个开发视角保留两个种子的完整测量输入，噪声汇总使用每像素三通道平均绝对误差。`validation/results.json` 给出所有分母、计数、测量值、预设门槛和各项是否通过。

两次渲染使用相同的降噪器和设置，测量改变采样种子带来的随机差异。估计降噪器的系统偏差需要独立的参照测量。

通道语义、数据边界和颜色变换的依据见 [Blender 渲染通道](https://docs.blender.org/manual/en/4.5/render/layers/passes.html)、[Blender 颜色管理](https://docs.blender.org/manual/en/4.5/render/color_management.html) 和 [OpenEXR Python 接口](https://openexr.com/en/latest/python.html)。

## 24 个家族的冻结与运行

正式清单在 `protocol/families-v1.json`。训练集为家族 001–016，开发集为 017–020，最终测试集为 021–024。训练集预先按编号分成四组，每组四个完整家族。场景版本、相机、示例 v01 和各条件的 trial ID 随清单冻结。研究预测、条件矩阵、分母和模型选择规则见 `protocol/study-v1.json`。工程桌面场景复用当时封存的源图、.blend、相机、参考和独立复核，并核对原 trial 选择文件的 SHA-256。

23 个新家族各自有按名称编写的物体组合和遮挡关系。在场景配置中可逐件检查书架、滑轮架、沥水架、抽屉、天平等布局的部件。它们共用一个米制摄影空间和同一套平移相机。固定的配置、相机和实现哈希在 `configs/formal-freeze-v1.json` 中；各家族另有剔除名称、编号和材质后的几何指纹，供检查重复布局。完整布局、.blend、参考图和几何数组仅在 Mac 评价端和研究归档使用。

下列命令分别用于静态核验和生成一个正式参考。第一条只读清单、几何定义、相机和哈希。第二条只生成选中的家族，然后在另一个记录器运行中重开其冻结场景、独立核验。每一条终端执行记录可独立封存。完成后，同一命令校验并返回已记录的结果。

```sh
.venv/bin/python scripts/formal_reference.py --validate-only
.venv/bin/python scripts/formal_reference.py --family scene_002_book_nook --store .research
```

正式生成写入独立的 `scene_render` 和 `archive_verify`，终端回执列出两个 run ID 和哈希。每个家族只有 source 一张实际输入，v01–v06 六张目标图均保留。v01 和 v02 用于相机几何检查与双种子噪声复核。正式场景按真实接收表面和首个遮挡物的 ID 分组计量露出宽度。两个开发视角各自至少有一对物体提供十像素连续水平宽度和二十四个非边缘像素。每个视角均保存原始像素数组、候选物体对总数及达到两项门槛的物体对统计。独立复核从存储数组逐行重新测量，并与第一遍统计比对。原工程场景保留指定红盒和蓝盒的遮挡验收。

正式 R1 从实际源 PNG 对每个 2×2 显示 sRGB 像素块求均值，再取最近的整数 8 位码值。只有恰好位于相邻整数中间时才取偶数。旧工程场景校准用的半尺寸预览采用 half-up。它属于训练家族，该家族只登记 B0。试验数据清单和每个来源包跟踪实际输入文件及其哈希。
